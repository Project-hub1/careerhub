# CareerHub Production Deployment

## Recommended: Render

This project includes `render.yaml`, `Procfile`, Gunicorn, PostgreSQL support, and `/health`.

1. Push this folder to a GitHub repository.
2. In Render, choose **New → Blueprint** and connect the repository.
3. Render reads `render.yaml` and creates the web service + PostgreSQL database.
4. Let the first build complete. It runs migrations and the idempotent seed script.
5. Open the generated `https://...onrender.com` URL.
6. Verify `https://YOUR-URL/health` returns `{"status":"ok","service":"careerhub"}`.

## Required production secrets

- `SECRET_KEY`: generated by Render through `render.yaml`, or set manually.
- `DATABASE_URL`: PostgreSQL connection string.
- Keep `DEV_SHOW_RESET_LINK=0` in production.

## Important production notes

- SQLite is retained only as a local-development fallback.
- PostgreSQL is used automatically when `DATABASE_URL` is set.
- Uploaded resumes currently use local disk. For multiple instances/ephemeral hosting, move resume uploads to S3-compatible object storage before scaling horizontally.
- `seed.py` is intended for demo data and is idempotent for the seeded jobs/companies. Remove the seed command from the build once the production database contains real client data.
- Before accepting real users, configure email delivery, backups, monitoring/error tracking, rate limiting, and a custom domain.
